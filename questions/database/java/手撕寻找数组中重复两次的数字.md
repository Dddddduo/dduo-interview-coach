# 手撕——寻找数组中重复两次的数字

## 🧠 联想记忆法

**核心记忆锚点：抽屉原理（Pigeonhole Principle）**
「n+1 个球塞进 n 个抽屉，必有一个抽屉装了两颗」——这是本题「重复值必然存在」的理论保证，也是面试开口第一句的底气。

**六种解法一句话记忆口诀：**
> 「哈希最快、排序最稳、符号标记最省、交换归位最巧、XOR 最挑、快慢指针最优雅」

- **哈希**（HashSet）→ 第一反应，通杀一切约束；
- **排序**（Sorting）→ 重复必相邻，思路朴素；
- **符号标记**（Sign-bit Marking）→ 把值当下标、用符号位当「已访问」标记；
- **值归位交换**（Cyclic Sort）→ 把每个值交换到它该在的下标，抽屉原理的工程化；
- **XOR** → 只有「恰一个数字重复两次、其余恰好一次」的严格版才能用；
- **Floyd 判圈**（快慢指针）→ 把数组想象成链表：`nums[i]` 就是下标 `i` 的 next 指针，重复值就是环的入口。

**场景触发联想：** 面试官说「O(1) 空间 + 不许改数组」→ 条件反射立刻想到快慢指针；说「随便写一个」→ 哈希 30 秒写完；说「值域是 [1,n]」→ 符号标记和交换归位登场。

## 📖 深度解答

## 1. 核心概念

题目原型是 LeetCode 287（Find the Duplicate Number）：给定长度 **n+1** 的整数数组，每个元素在区间 **[1, n]** 内，假设至少存在一个重复数字，找出它。

**先澄清题面歧义（面试加分项）**——本题名曰「重复两次」，至少有四层含义需要确认：

1. **数组范围**：值是否限定在 [1, n]？是否全为正数？这决定符号位标记法、原地交换法能否使用；
2. **重复次数上限**：是「恰有一个数字重复两次、其余各出现一次」（严格版），还是「至少重复一次、可能重复多次」（宽松版）？只有严格版才能用 XOR；
3. **能否修改数组**：决定 O(1) 空间的原地算法是否合法；
4. **找「一个」还是「全部」重复数字**：判圈法只能找一个，找全部必须用计数哈希。

**核心术语（中英对照）：** 重复数字（Duplicate Number）、哈希表（Hash Table）、抽屉原理（Pigeonhole Principle，即鸽笼原理）、原地算法（In-place Algorithm）、快慢指针 / Floyd 判圈算法（Floyd's Cycle Detection，也叫龟兔赛跑 Tortoise and Hare）、异或（XOR）、循环排序（Cyclic Sort）。

## 2. 底层原理

### 解法谱系与复杂度对比

| 解法 | 时间复杂度 | 空间复杂度 | 是否修改数组 | 适用前提 |
|---|---|---|---|---|
| 哈希表计数 | O(n) | O(n) | 否 | 无任何前提，通用 |
| 排序 + 相邻扫描 | O(n log n) | O(1)（原地排序） | 是 | 允许修改数组 |
| 符号位标记 | O(n) | O(1) | 是（破坏数据） | 值域 [1, n] 且全为正 |
| 原地交换（抽屉原理） | O(n) 摊还 | O(1) | 是 | 值域 [1, n] |
| XOR 位运算 | O(n) | O(1) | 否 | 恰一个重复两次，其余恰好一次 |
| Floyd 判圈（快慢指针） | O(n) | O(1) | 否 | 值域 [1, n]，至少一个重复 |
| 二分答案 + 计数 | O(n log n) | O(1) | 否 | 至少一个重复（加分扩展） |

**逐条原理拆解：**

**(1) 哈希表法**：遍历时把每个数加入 `HashSet`，`add()` 返回 `false` 说明已存在，即为重复。复杂度 O(n)/O(n)，无需任何前提，是保底答案。找「全部出现两次的数」则用 `HashMap` 计数后筛选 value == 2。

**(2) 排序法**：重复数字排序后必然相邻，扫描一遍比较 `nums[i] == nums[i-1]`。`Arrays.sort` 对原始类型数组走双轴快排（Dual-Pivot Quicksort），原地排序 O(1) 额外空间，但破坏了原始顺序。

**(3) 符号位标记法**：这是「把原数组当作布尔标记数组」的经典洞察。用值 `num` 作下标访问 `nums[num]`，将其取负打上「已访问」标记；若访问前发现目标位置已为负数，说明这个值出现过一次，即为重复。注意：遍历时值可能已被取负，**必须先取 `Math.abs` 还原**才能当下标，这是手写 bug 的高发区。

**(4) 原地交换 / 抽屉原理**：理想状态下，下标 `i` 的位置应存放值 `i+1`。遍历时把 `nums[i]` 交换到它应属的位置 `nums[nums[i]-1]`；若目标位置已存放相同值，说明它就是重复值。时间复杂度摊还（amortized）O(n)——因为每次交换都至少把一个元素送到最终位置，总交换次数不超过 n。

**(5) XOR 位运算**：利用三条性质——`a ^ a = 0`、`a ^ 0 = a`、异或满足交换律与结合律。把数组全部元素与 1..n 全部异或，所有「成对」出现的数字两两抵消，剩下的就是重复值。**前提极其苛刻**：只有「恰一个数字出现两次、其余各出现一次」的严格版适用。LeetCode 287 原题中重复值可能重复多次、其余数字出现次数不定，XOR 无法抵消干净——这是最经典的答错陷阱。

**(6) Floyd 判圈法**：把数组抽象成**函数轨道图**（Functional Graph）：下标 `i` 的「指针」指向 `nums[i]`。值域 [1, n] 保证不会越界；存在重复值 d 意味着至少两个不同下标指向 d，必有「分叉」成环，且**环的入口就是重复值**。快慢指针：slow 每次走一步（`slow = nums[slow]`），fast 走两步（`fast = nums[nums[fast]]`）；相遇后 slow 从 0 重新出发，两者同速再走到相遇处，即环入口。正确性证明一句话：设起点到环入口距离为 a、环长为 b，相遇点距环入口为 x，则 fast 步数是 slow 的两倍：`2(a+x) = a + b + x ⇒ a = b − x`——即「起点到入口」恰等于「相遇点继续走到入口」，所以从头和相遇点同速走必然在入口（重复值）相会。

**(7) 二分答案 + 计数**（可选加分）：对值域 [1, n] 二分候选值 mid，统计数组中小于等于 mid 的元素个数，若大于 mid 说明重复值在左半区间。O(n log n) 时间、O(1) 空间、不修改数组、无「只能重复一次」前提——但不能找全部重复值。

## 3. 实践应用

### 完整可运行 Java 代码（六解法全家桶 + 全重复变体）

```java
import java.util.*;

/**
 * 寻找数组中重复两次的数字 —— 解法全家桶 (LeetCode 287 变体)
 * 前提约定: 数组长度 n+1, 元素取值范围 [1, n]
 */
public class FindDuplicate {

    // ========== 解法一: 哈希集合 (通用, 最稳) ==========
    // 时间 O(n), 空间 O(n), 不改数组, 无值域前提
    public static int findDuplicateHashSet(int[] nums) {
        Set<Integer> seen = new HashSet<>();
        for (int num : nums) {
            if (!seen.add(num)) {
                return num; // add 返回 false 说明已存在
            }
        }
        return -1;
    }

    // ========== 解法二: 排序 + 相邻扫描 ==========
    // 时间 O(n log n), 空间 O(1) (原地排序), 会修改数组
    public static int findDuplicateSort(int[] nums) {
        Arrays.sort(nums);
        for (int i = 1; i < nums.length; i++) {
            if (nums[i] == nums[i - 1]) {
                return nums[i];
            }
        }
        return -1;
    }

    // ========== 解法三: 符号位标记 (值域 1..n, 全为正数) ==========
    // 时间 O(n), 空间 O(1), 会修改数组 (破坏原值)
    public static int findDuplicateMark(int[] nums) {
        for (int num : nums) {
            int idx = Math.abs(num);          // 原值可能已被取负, 必须先还原
            if (nums[idx] < 0) {
                return idx;                   // 该下标已被标记过 -> 重复
            }
            nums[idx] = -nums[idx];           // 打标记: 把 nums[idx] 取负
        }
        return -1;
    }

    // ========== 解法四: 原地交换 / 抽屉原理 (值归位) ==========
    // 时间 O(n) 摊还, 空间 O(1), 会修改数组
    public static int findDuplicateSwap(int[] nums) {
        int n = nums.length;
        int i = 0;
        while (i < n) {
            if (nums[i] != i + 1) {           // 值 i+1 应放在下标 i
                int target = nums[i] - 1;
                if (nums[target] == nums[i]) {
                    return nums[i];           // 目标位置已有相同值 -> 重复
                }
                int tmp = nums[i];            // 交换, 把一个元素送到最终位置
                nums[i] = nums[target];
                nums[target] = tmp;
            } else {
                i++;                          // 已归位才前进
            }
        }
        return -1;
    }

    // ========== 解法五: XOR (仅限严格版: 恰一个数字重复两次, 其余恰好一次) ==========
    // 时间 O(n), 空间 O(1), 不改数组
    public static int findDuplicateXor(int[] nums) {
        int n = nums.length - 1;              // 数组长度 n+1
        int x = 0;
        for (int num : nums) {
            x ^= num;                         // 数组全部元素
        }
        for (int v = 1; v <= n; v++) {
            x ^= v;                           // 再异或 1..n, 成对者全部抵消
        }
        return x;                             // 剩下的就是重复值
    }

    // ========== 解法六: Floyd 快慢指针 (O(1) 空间 + 不改数组, 终极答案) ==========
    // 时间 O(n), 空间 O(1), 不修改数组
    public static int findDuplicateFloyd(int[] nums) {
        int slow = nums[0];
        int fast = nums[nums[0]];
        while (slow != fast) {                // 第一阶段: 找相遇点
            slow = nums[slow];
            fast = nums[nums[fast]];
        }
        slow = 0;                             // 第二阶段: 从头同速走
        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];
        }
        return slow;                          // 环入口 = 重复值
    }

    // ========== 附: 找"所有"恰好出现两次的数字 (通用版) ==========
    public static List<Integer> findAllTwice(int[] nums) {
        Map<Integer, Integer> count = new HashMap<>();
        for (int num : nums) {
            count.put(num, count.getOrDefault(num, 0) + 1);
        }
        List<Integer> res = new ArrayList<>();
        for (Map.Entry<Integer, Integer> e : count.entrySet()) {
            if (e.getValue() == 2) res.add(e.getKey());
        }
        return res;
    }

    public static void main(String[] args) {
        int[] nums = {3, 1, 3, 4, 2};         // 1..4 各一次 + 3 重复两次
        System.out.println("HashSet : " + findDuplicateHashSet(nums.clone()));
        System.out.println("Sort    : " + findDuplicateSort(nums.clone()));
        System.out.println("Mark    : " + findDuplicateMark(nums.clone()));
        System.out.println("Swap    : " + findDuplicateSwap(nums.clone()));
        System.out.println("XOR     : " + findDuplicateXor(nums.clone()));
        System.out.println("Floyd   : " + findDuplicateFloyd(nums.clone()));
        System.out.println("AllTwice: " + findAllTwice(nums));
    }
}
```

**输出**：前六种方法均返回 `3`，`findAllTwice` 返回 `[3]`。`main` 中刻意使用 `clone()`，因为排序/标记/交换三个解法会修改原数组，保证每个解法都跑在原始数据上。

### 面试现场选择逻辑

| 现场场景 | 首选解法 |
|---|---|
| 要求手写最快、思路优先 | 哈希表法（30 秒完成） |
| 要求 O(1) 空间，允许改数组 | 符号标记法或原地交换法 |
| 要求 O(1) 空间且**不许改数组** | **Floyd 判圈法（必须答出）** |
| 严格版「恰一个重复两次」 | XOR 一句带过，展示位运算功底 |
| 找全部重复两次的数 | HashMap 计数（判圈法无法推广） |
| 只读 + 想展示扩展 | 二分答案 + 计数 |

**选择逻辑的本质**：先满足「能解」（哈希），再压空间（排序/标记/交换），最后顶满约束（O(1) + 只读 → Floyd）。这套「由浅入深、逐一解锁约束」的递进本身就是面试官想看的工程思维。

## 4. 深入思考

- **为什么 Floyd 能 O(1) 空间 + 不修改数组？** 它把数组自身的下标连接关系当「额外存储」使用——本质和符号位标记一样，是「借用已有数据结构的状态」。一个借符号位、一个借索引结构，殊途同归。信息论上，重复值的身份至少需要 log n 位信息，而数组的索引关系恰好提供了这些位。
- **判圈法正确性依赖什么？** 值域 [1, n] 保证映射 `f(i) = nums[i]` 始终合法；重复值 d 意味着至少两个下标指向它，函数轨道图（Functional Graph）中必有环，且环入口就是 d——这是把「数组查重」抽象成「图论判环」的思维跃迁。
- **变体拓展**：(a) 找缺失数字（Missing Number）——XOR 同样适用；(b) 找全部重复/全部缺失（LeetCode 442/448）——符号位标记一趟扫完输出下标；(c) 值域含 0 或负数——符号位法需处理下标 0 的特殊性和平移；(d) 只读不可变数组——只有哈希、二分、XOR、Floyd 合法。
- **工程类比**：符号位标记 ≈ 布隆过滤器（Bloom Filter）的「打点」思想；值归位交换 ≈ 计数排序（Counting Sort）的原地变体；快慢指针还可用于判链表环、找链表中点。掌握这一题 = 掌握四个底层工具箱。

## 🗺️ 回答思路

## 答题逻辑框架

1. **确认环节（约 20 秒）**：复述题面 + 澄清约束。示例话术：「我先确认一下：数组长度是 n+1、值域是 [1, n] 吗？是恰好一个数字重复两次，还是允许重复多次？原数组允许修改吗？需要找全部还是任意一个？」——这个提问直接拉开档次。
2. **由浅入深**：哈希（先给，证明能解）→ 空间优化（排序/符号标记/值归位）→ 终极约束（O(1) 空间 + 只读 → Floyd 判圈）。每个解法讲清三件事：**前提、复杂度、为什么正确**。
3. **收尾**：给复杂度权衡表 + 边界处理（空数组、n=1、无重复时返回什么需与面试官约定）。

## 重点得分点

- **澄清约束的提问**——最大加分项，90% 的候选人直接闷头写码；
- **复杂度表述准确**：哈希 O(n)/O(n)、排序 O(n log n)/O(1)、Floyd O(n)/O(1)；
- **主动指出 XOR 的前提限制**（恰一个重复两次且其余恰好一次）——多数人栽在这，说出来即是亮点；
- **Floyd 第二阶段 slow 必须从 0 重新出发**，并附一句话证明「相遇点到入口距离 = 起点到入口距离」；
- **明说修改类解法的破坏性**：「以下解法会修改原数组，如果要求只读需要换思路」——体现数据安全意识。

## 常见误区

1. **哈希空间误判**：说 HashSet 是 O(1) 空间。实际最坏 O(n)，面试官追问空间复杂度时被打脸。
2. **符号标记忘了取绝对值**：值可能已被前一步取负，直接当下标会越界或错位——手写 bug 最高发区，必须 `Math.abs(num)`。
3. **XOR 前提误用**：拿 LeetCode 287 原题直接上 XOR——原题允许重复多次、其他数字出现次数不定，抵消不干净，答案错误。
4. **原地交换忘控制 i 的推进**：交换后当前下标可能仍未归位，直接 `i++` 会跳过元素；未归位时应继续处理而非前进。
5. **Floyd 第二阶段起点写错**：必须 `slow = 0` 重走，而不是在相遇点继续——最常见的实现错误。
6. **不问返回约定**：题面保证存在时无需哨兵；否则返回什么（如 -1）应先与面试官确认。

- **0–1 分钟**：澄清约束；
- **1–4 分钟**：哈希 + 排序（各 30 秒写出代码，展示速度）；

## 过渡话术

- 哈希 → 优化：「如果面试官要求 O(1) 空间，哈希就不行了，我们需要利用值域在 [1, n] 这个约束。」
- 标记 → 判圈：「上面两种 O(1) 解法都修改了数组；如果题目要求只读，就得换思路——把数组当成链表，用快慢指针找环。」
- XOR → Floyd：「XOR 虽然简洁，但要求恰好一个数字重复两次、其余恰好一次，原题不满足，所以我们用更通用的判圈法。」
- 收尾总结：「一句话总结：时间上哈希最优，空间和只读约束下 Floyd 最优，面试中按约束选型即可。」
