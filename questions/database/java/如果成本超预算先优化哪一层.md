# 如果成本超预算，先优化哪一层？

# 如果成本超预算，先优化哪一层？

## 🧠 联想记忆法

**一句话记忆：先看账单再动刀，省钱六招「缓、缩、路、限、收、换」。**

类比"减肥"来记：
1. **先量体脂再减肥**——对应"成本归因（cost attribution）"：不拆账单就动手，等于不知道脂肪在哪就节食；
2. **先戒含糖饮料**——对应"Prompt 前缀缓存（prompt caching）"：最无痛、零风险、收益最大；
3. **再少吃一口**——对应"压缩输入（input compression）"：少发 token 就是少花钱；
4. **再替换食材**——对应"模型路由（model routing）"：小模型干小活，就像鸡胸肉代替五花肉；
5. **再控制份量**——对应"限制输出（output capping）"：max_tokens + 结构化输出，防止"输出暴食"；
6. **最后才上手术**——对应"换更便宜的模型/微调小模型"：全局大改动、风险高，永远放在最后。

再记**排序逻辑**（为什么是这个顺序）：`缓存、压缩`不碰模型不改效果（零风险）→ `路由、限长`每查询决策一次（低风险）→ `检索收紧`动了效果敏感变量（中风险）→ `换模型/微调`全局牵一发动全身（高风险）。**风险从低到高、收益从稳到险**，这就是性价比排序。

## 📖 深度解答

## 1. 核心概念

成本超预算（budget overrun）时，最忌讳的就是"拍脑袋换个便宜模型"。这是一个系统工程，核心概念有三个：

- **成本归因（cost attribution）**：把总账单（billing）通过埋点（instrumentation）拆解成 token 消耗结构——输入 vs 输出、Prompt 里的固定系统提示 vs 检索证据 vs 历史对话 vs 工具调用（tool calls），并按功能/用户两个维度切片。**没有归因，不优化**：你不知道钱花在哪，就不知道刀往哪砍。
- **优化优先级按性价比（cost-performance ratio）排序**：不是"省得多就优先"，而是"节省比例 / 质量风险 / 改动成本"三者权衡。
- **北极星指标是单位成本质量比（quality per dollar）**：我们优化的不是"最便宜"，而是"每一块钱买到的质量"。

## 2. 底层原理

LLM 计费的本质是：**总成本 = 输入 token × 输入单价 + 输出 token × 输出单价**。这决定了三个隐藏事实：

1. **输入通常占大头且高度冗余**。每次请求，系统提示、工具定义、历史上下文都会原样重复发送，模型要为这些 token 重新做 prefill 计算。这就是 Prompt 缓存（prompt caching）能成为第一杠杆的原因：它复用 KV 缓存（KV cache），命中的前缀**只收约 1/10 的钱、甚至更低**，而模型看到的输入完全不变——**质量零风险**。主流厂商的具体机制：Anthropic 缓存读（cache read）打 0.1×（省 90%），缓存写（cache write）收 1.25× 溢价；OpenAI 自动前缀缓存（旧型号 50% 折扣、新旗舰约 90%）；Google Gemini 按存储小时计费。这也是题目里"成本降 80% 级"的依据。
2. **输出 token 单价通常是输入的 3~5 倍**（例如 $3/M 输入 vs $15/M 输出）。所以"限制输出"是直击最贵单价的杠杆：max_tokens 收敛、结构化输出（structured output）约束格式，都能直接砍钱。
3. **不同模型的推理成本差一个数量级**（小模型 vs 旗舰模型），但真实流量里大多数请求是简单请求——这是模型路由（model routing）成立的前提：难度分层是客观存在的。

而"换更便宜的模型/微调"为什么必须放最后？因为它是一个**全局杠杆**：质量要全面回归评估；且**换模型会清空缓存**（缓存是模型级别的，新模型要把整个前缀按原价重算），之前的缓存收益瞬间归零；微调还要数据、训练、评测周期。一次改动，牵动缓存、路由、评估所有系统。

## 3. 实践应用

**Step 0 — 成本归因（没有归因不优化）**
- 每一请求记录：model、input_tokens、output_tokens、cache_read、cache_creation、功能 ID、用户 ID、时间戳；
- 按两个方向拆：①结构维度：输入 vs 输出；Prompt 固定部分 vs 检索证据 vs 历史 vs 工具调用——办法是把固定前缀单独标记，或用缓存命中的 token 数倒推；②业务维度：按功能（Top 功能排行）、按用户（P95 单用户成本）。
- 你会发现 80/20：往往 2 个功能、5% 的用户吃掉了 60% 的账单。

**Step 1 — Prompt 前缀缓存**（成本降 80% 级）
- 把系统提示、工具定义、常驻文档排成稳定前缀，打缓存断点（cache_control）；监控缓存命中率（cache hit rate），健康值应 > 0.8，低于 0.3 说明断点打在了易变内容上。

**Step 2 — 压缩输入**
- 减少历史（窗口截断、先摘要再入参）、检索证据去噪（只留高相关块）、精简系统提示、紧凑格式（压缩 JSON、删冗余 few-shot）。压缩工具（如 LLMLingua 类）可做到数倍压缩。

**Step 3 — 模型路由**
- 简单任务（分类、抽取、格式化）走小模型，复杂任务（推理、规划、长文生成）走大模型；路由决策可以是规则（长度/意图关键词）、embedding 相似度、或小模型难度分类器。

**Step 4 — 限制输出**
- max_tokens 收敛到业务上限；用 JSON schema / function calling 让输出"定型定量"，杜绝模型废话。

**Step 5 — 收紧检索预算**
- 调小检索块数（top-k）和块长（chunk size），减少塞进 prompt 的证据量。

**Step 6 — 最后才换更便宜的模型 / 微调小模型**
- 全局评估质量、重做缓存布局与路由策略，微调小模型要拿评测集证明"在业务分布上不掉点"。

**量化收益方法（贯穿全程）**：每项优化上线前先估算节省比例（预估 ROI），上线后做 A/B 验证质量不回退（效果指标 diff 在置信区间内），再对比实际节省金额 vs 预估，形成闭环。

**工程机制**：日/月预算告警 + 单用户成本上限（cost cap），超过阈值触发告警；成本看板（cost dashboard）按功能/用户/模型实时展示；预算耗尽时自动降级（graceful degradation）——降模型档位、关非核心功能、拉高缓存复用，这一部分正是"第 55 题（超支自动降级）"的策略落地，这里负责触发与策略排序。

## 4. 深入思考

- **成本与质量的平衡**：不能无脑省钱。省钱方案必须"质量中性或可回退"——缓存、压缩、限长属于前者；砍检索证据属于后者，砍过头就是幻觉率（hallucination rate）上升，隐性损失远超省下的钱。
- **quality per dollar 才是北极星**：举个例子，小模型单次便宜 10 倍但正确率 80%，大模型贵 10 倍但 95%——纯算 token 觉得小模型赢，但算"每个正确回答的成本"可能大模型更优。一切优化决策都应回到这个比值。
- **缓存命中率是长期健康指标**：不仅监控它，还要分析 miss 的原因（断点位置、前缀易变性、模型切换），把"缓存友好"（cache-friendly）当成 prompt 设计的约束。
- **更深一层的协同**：模型路由和缓存会互相打架——换模型即清缓存。所以多轮 agent 场景里，路由要尽量发生在会话边界而非中途；缓存、压缩、路由要当成一个联合优化问题，而不是三件独立的事。

## 🗺️ 回答思路

**答题逻辑框架（总—分—总）**：
1. 一句话亮结论："先做成本归因，再按性价比六步优化：缓存→压缩→路由→限输出→收紧检索→最后换模型。"
2. 归因：账单+埋点拆 token 结构，强调"没有归因不优化"；
3. 六步优先级：每一步一句话讲清"省什么钱、什么风险、为什么这个位次"；
4. 量化与机制：预估 ROI、A/B 验证、预算告警/看板/超支降级（联动第 55 题）；
5. 收尾升华：quality per dollar 北极星 + 成本质量平衡 + 缓存命中率监控。

**重点得分点**：
- 主动先讲"归因"，而不是上来就报方案——体现工程思维；
- 明确说出"排序依据是性价比/风险，不是省钱绝对值"；
- 量化意识：每项优化给出节省量级与验证方法；
- 系统意识：告警、看板、自动降级，说明你做过生产环境。

**常见误区**：
- 只盯总账单不做归因，方案全凭猜；
- 上来就换便宜模型——显外行，且忽略换模型会清空缓存、质量全面回退；
- 为了省钱猛砍检索证据，幻觉率上升，隐形成本翻倍；
- 只谈"省了多少"不谈"质量有没有掉"，缺 A/B 闭环。

**时间分配建议**（总共约 3~4 分钟）：开场定框架 20 秒；归因 40 秒；六步优先级 1 分半；量化与工程机制 40 秒；平衡思考收尾 30 秒。

**过渡话术**：
- 从归因到方案："归因之后我们发现，80% 的钱花在输入 token 上，而其中一大半是重复发送的固定前缀——所以第一刀砍缓存。"
- 从方案到机制："方案落地必须配工程护栏，否则下个月又会超，所以我还会加预算告警和自动降级。"
- 收尾："最后我想强调的是，省钱不是目的，quality per dollar 才是——所有优化都要回到这个比值来验证。"
