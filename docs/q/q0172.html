什么是全双工，什么是半双工？

什么是全双工，什么是半双工？

什么是全双工，什么是半双工？

🧠 联想记忆法

一条公路，三种形态。

想象一条连接两座城市的公路：
- 单工（Simplex）：单行道。车永远只能从 A 城开往 B 城，反向不通行。就像广播电台，信号永远只从发射塔流向收音机。
- 半双工（Half-duplex）：双向单车道窄桥。两个方向都能走，但同一时刻桥上只允许一个方向的车——桥头放一个"交通信号灯"轮流放行。就像对讲机，"按住说话（Push to Talk, PTT）"才能讲，松手才能听，两个人同时说话只会互相盖住对方。
- 全双工（Full-duplex）：双向多车道高速公路。两个方向各有独立车道，A 到 B 的车和 B 到 A 的车同时飞驰，互不干扰。就像打电话，你说我听、我说你听是同时发生的。

三字口诀：单一条（单向一条道），半轮流（轮流放行），全并行（双向并行）。

英文钩子："half-duplex" 是只用到双工（duplex，双向）能力的一半——要么发、要么收；"full-duplex" 是完整发挥——同时收发。记不住时想想"半=轮流、全=同时"就够了。

📖 深度解答

1. 核心概念

三种通信模式描述的是数据传输方向性，判定标准只有一个：同一时刻能否双向传输。

  • 单工（Simplex）：数据传输方向固定，永远单向。发送方只能发，接收方只能收，角色不可互换。典型例子：广播（Radio/TV Broadcast）、电视遥控器、温湿度传感器上报数据给单片机。
  • 半双工（Half-duplex）：通信双方都能收、也能发，但同一时刻只能有一个方向在传输，需要"轮流"。典型例子：对讲机（Walkie-talkie）、RS-485 总线、早期共享式以太网（Hub + CSMA/CD）。
  • 全双工（Full-duplex）：通信双方同一时刻既可以发送又可以接收，双向数据流互不阻塞。典型例子：电话（Telephone）、现代以太网（双绞线各自独立收发）、TCP 连接、WebSocket。

区分难点：单工与半双工的关键区别是"能否反向"——广播不能反着回答你，但对讲机可以；半双工与全双工的关键区别是"能否同时"——对讲机同一时刻只有一个人能讲话，电话可以两人同时说。

2. 底层原理

三种模式的本质差异在物理层信道组织方式：独立信道 vs 共享信道分时切换。

单工：只需一条单向信道，实现最省。广播发射塔占用一个频段持续发射，收音机只需要接收电路，没有接收方向上的任何冲突问题。

半双工：多个方向共享同一条物理信道（一根线、一个频段、一束光），因此必须通过介质访问控制（Media Access Control, MAC）来仲裁"此刻归谁用"，并引入收发切换开销：
- RS-485：一对双绞线上挂多个节点，谁要发送谁就使能自己的驱动器（Driver Enable），发送完立刻释放，其他节点才能回话——本质上就是"占总线，轮流讲"。
- 早期以太网：所有节点共享一条同轴电缆或经集线器（Hub）共享一段介质，采用 CSMA/CD（Carrier Sense Multiple Access with Collision Detection，载波侦听多路访问/冲突检测）：先听后发、边发边听，一旦检测到冲突（Collision）就随机退避（Exponential Backoff）后重传。所有共享这段介质的节点构成一个冲突域（Collision Domain），负载越高冲突越多，有效吞吐急剧下降。
- 对讲机/无线半双工：同一频率无法边发边收（自身发射会淹没接收），必须收发切换（Turnaround Time），PTT 按键就是手动切换开关。

全双工：为每个方向分配独立的物理信道，收发彻底解耦：
- 现代以太网（双绞线，Twisted Pair）：以 100BASE-TX 为例，4 对线中 1 对专门发送（TX）、1 对专门接收（RX），两个方向数据流物理上互不接触，自然不需要 CSMA/CD，也没有冲突域——这就是"全双工为什么需要双绞线独立线对"的根本原因。
- 光纤（Optical Fiber）：要么用两芯光纤各走一个方向，要么用波分复用（Wavelength Division Multiplexing, WDM）在同一根光纤上以不同波长同时收发。
- 无线蜂窝网络：FDD（Frequency Division Duplexing，频分双工）用上行/下行两个独立频段实现同时收发；而 TDD（Time Division Duplexing，时分双工）上下行分时使用同一频段，本质是"无线侧的半双工"。
- UART（Universal Asynchronous Receiver/Transmitter，通用异步收发器）：物理上 TX 引脚与 RX 引脚完全独立，因此硬件天然支持全双工；但如果传输介质只有一根线（如 1-Wire、I2C 的 SDA），或协议规定分时通信（如 RS-485 总线仲裁），则表现为半双工。

一句话总结原理：半双工是"一条路，轮流用"，靠协议调度避免碰撞；全双工是"两条路，各走各的"，靠物理信道隔离消除碰撞。

3. 实践应用

工程应用矩阵：

模式 典型场景 物理实现 代价/特点
单工 广播、红外遥控、传感器上报 一条单向信道 最省资源，无法应答
半双工 对讲机、RS-485 工业总线、Hub 以太网、Wi-Fi（CSMA/CA） 共享介质 + 介质访问控制 需切换时间，有冲突域，吞吐受限
全双工 电话、双绞线以太网（Switch 组网）、光纤骨干、TCP/WebSocket 独立收发信道 需双倍资源（线对/频段），双向线速

关键工程案例拆解：

  • 以太网 Hub vs Switch：Hub 是把所有端口物理上"并"到一段共享介质，天然半双工、有冲突域；交换机（Switch）把每个端口做成点对点（Point-to-Point）全双工链路，端口间数据流互相隔离，冲突域缩小到"只剩一个端口"，CSMA/CD 因此被彻底边缘化——这也是为什么现代网卡/交换机都强制全双工，半双工以太网如今只在兼容性模式中出现。
  • HTTP vs WebSocket：HTTP/1.1 是"请求-响应"语义——客户端发请求后必须等响应，同一连接上双方不会同时主动发数据，这是应用层协议语义上的半双工（也有人叫请求响应式单工/半双工）。而 WebSocket 在 TCP 之上提供应用层全双工：客户端和服务端可以随时同时互发消息（如聊天、行情推送），但底层传输仍依赖 TCP 的全双工能力。
  • TCP 是全双工的：TCP 连接建立后，双方各维护独立的发送缓冲区和接收缓冲区，两条方向相反的字节流同时流动，各自有独立的序号（Sequence Number）与确认（Acknowledgment），确认报文还可以捎带（Piggyback）在反向数据里，双向互不阻塞。

4. 深入思考

第一层：分层看待"双工"。全双工/半双工首先是物理层关于信道组织方式的事实，但工程上人们常把它引申到协议语义层面：TCP 是全双工协议，HTTP/1.1 却在应用层呈现请求-响应（半双工）语义，WebSocket 又回到全双工语义。面试时主动讲清"物理层能力 vs 协议层语义"这个分层视角，是加分点。

第二层：全双工是"昂贵"的。全双工需要为反向方向单独配置信道资源（多一对线、多一根纤、多一个频段），这是物理成本；半双工省资源、能挂多节点（RS-485 总线拓扑），但付出的是切换时间和冲突仲裁的代价。工程选型的本质是资源成本与吞吐效率的权衡。

第三层：几个值得提前准备的追问：
- 为什么 TCP 能全双工？ 因为底层物理链路提供了独立双向信道（双绞线两对线/光纤双纤），且 TCP 协议本身为两个方向各自维护独立的字节流、序号和确认机制。
- 为什么半双工会产生冲突域？ 因为共享介质上多个节点同时发送会互相叠加破坏（冲突），冲突域就是"一次只能有一个节点成功发送"的介质范围；全双工点对点链路中只有一台对端，收发信道分离，冲突不可能发生。
- CSMA/CD 为什么被淘汰？ 不是机制错了，而是共享介质拓扑被交换机全双工点对点替代，冲突的前提"共享介质"消失了。
- 无线为什么普遍半双工？ 同一频率上收发会自我干扰，除非用 FDD 分离频段——这也解释了 4G/5G 为什么有 TDD/FDD 之分。

第四层：对业务性能的影响。半双工在低负载下问题不大，高负载时冲突/退避使有效吞吐骤降；全双工双向可同时达到线速（Line Rate），这正是数据中心普遍要求全双工的原因。回答收尾时可以提一句"从 Hub 到 Switch 的演进史，就是冲突域不断缩小的历史"，把知识点串成一条技术史脉络。

🗺️ 回答思路

答题逻辑框架

定义 → 原理 → 例子 → 影响（四步框架）：
1. 定义：一句话点出判定标准——"按同一时刻能否双向传输区分"，给出三种模式的英文对照。
2. 原理：落到物理层——单工一条单向信道；半双工共享信道+分时仲裁（CSMA/CD、PTT）；全双工独立信道（双绞线两对线、FDD）。
3. 例子：对讲机（半双工）、电话/现代以太网（全双工）、广播（单工），再补 UART、RS-485、Hub/Switch、HTTP/WebSocket/TCP 的分层例子。
4. 影响：冲突域、吞吐差异、资源成本，落到"为什么工程上从半双工走向全双工"。

重点得分点

  1. 判定标准表述准确："同一时刻"三个字是灵魂，很多人只答"双向传输"而漏了"同时"。
  2. 能讲清物理实现差异：独立信道 vs 共享信道切换，提到双绞线独立线对、CSMA/CD、冲突域。
  3. 有分层视角：区分物理层全双工与 HTTP 应用层请求-响应语义，这是拉开差距的地方。
  4. 应用矩阵丰富：UART 可全双工、RS-485 半双工、Hub 半双工/Switch 全双工、TCP/WebSocket 全双工、HTTP/1.1 半双工语义——例子越具体越显功底。
  5. 收尾有高度：从"Hub→Switch 演进=冲突域消失"或"成本与效率权衡"升华。

常见误区

  • ❌ 把对讲机说成"单工"——对讲机可收可发，只是不能同时，是半双工；广播才是单工。
  • ❌ 说"UART 是半双工"——UART 的 TX/RX 引脚独立，硬件支持全双工；半双工与否取决于总线/协议（RS-485、I2C、1-Wire 才是半双工）。
  • ❌ 混淆协议语义与物理能力——说"TCP 是请求响应的"或"HTTP 是全双工的"都不准确，要分层说明。
  • ❌ 只说"全双工就是能同时收发"却解释不了为什么能——必须落到"独立物理信道"。
  • ❌ 忘了点名冲突域与 CSMA/CD 的关系——这是半双工的核心代价。

时间分配建议（总计 2~3 分钟）

  • 0~30 秒：定义三模式 + 判定标准（"同一时刻能否双向"），给对讲机/电话两个例子。
  • 30 秒~1.5 分钟：原理——共享信道 vs 独立信道，讲 CSMA/CD、冲突域、双绞线两对线、UART 原理。
  • 1.5~2.5 分钟：应用矩阵 + 分层视角（Hub/Switch、HTTP/WebSocket/TCP）。
  • 最后 30 秒：总结影响与演进趋势，留一个"您想让我展开哪个方向？"的收口。

过渡话术

  • 定义→原理："刚才说的是'是什么'，其实这三种模式最本质的差异在物理实现——也就是信道怎么组织。"
  • 原理→应用："理解了信道组织方式，我们再看工程上怎么用——这里有一张应用矩阵。"
  • 应用→收尾："最后从工程演进的角度总结一句：从 Hub 到 Switch 的历史，就是冲突域不断缩小、通信从半双工走向全双工的历史。"
